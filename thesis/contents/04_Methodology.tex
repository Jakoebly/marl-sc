\section{The Supply Chain Model as a Cooperative Partially Observable Markov Game}
\label{sec:supply-chain-pomg}
In order to consistently apply \gls{acr:marl} methods, we model the distribution network of \autoref{chap:problem-formulation} as a finite-horizon, discounted \gls{acr:pomg}. In this section, we thus specify the central \gls{acr:pomg} components in the context of our distribution network and outline our design of the observation functions $O^i$, the state space $\mathcal{S}$, the action space $\mathcal{A}$, and the reward functions $R^i$.\\   

\subsection{Observation Design}
\label{subsec:observation-design}
We treat the warehouses as the agents of the game such that $\mathcal{I}=\mathcal{W}$ and agent $i$ is warehouse $i$. The game therefore has $N=W$ agents that need to make decisions on their replenishment orders by interacting with the environment. This environment is the distribution network of \autoref{chap:problem-formulation} and applying a deep learning architecture to this setting requires a formal specification of the features that agents observe and act on. Broadly, this can be approached in two ways. 
One method favors a minimal feature set to obtain a minimum viable observation space $o_{it}^{min}$ that contains only the most essential information needed to describe each agent's local situation. The idea behind this approach is that a sufficiently deep \gls{acr:nn} could itself learn an effective policy by abstracting complex relationships from these basic features such that explicit feature engineering becomes unnecessary [\textbf{CITE: paper that shows this}].
For instance, a minimal feature set for our setting would expose only the current inventory state of the agent, which is fully characterized by its on-hand inventory $I_{ikt}$ and its outstanding orders by arrival slot $\mathbf{P}_{ikt} = \left( q_{ik,\,t-L_{ik}+1},\ \dots,\ q_{ikt} \right)$, so that $ o_{it}^{min} = [ (I_{ikt})_{k \in \mathcal{K}},\ (\mathbf{P}_{ikt})_{k \in \mathcal{K}} ]$ for all agents. In fact, for a single warehouse under stationary demand, lost sales, and a fixed lead time the inventory state is a sufficient statistic for the optimal ordering policy [\textbf{CITE: inventory position as a sufficient statistic, {karlin1958lostsales}}].

However, since we consider the multi-agent case in which the agents are coupled through transshipment, a single agent's local state is no longer a sufficient statistic and we can thus not rely on the single-installation result of [\textbf{CITE:{karlin1958lostsales}}]. Additionally, both prior work and our own experiments indicate that incorporating a broader set of features significantly improves convergence speed, final policy performance, and model interpretability [\textbf{CITE: benefits of feature engineering in (multi-agent) RL for inventory control, {glanois2024survey}}]. As part of our feature engineering process, we have therefore designed a more refined set of features that incorporates our prior understanding of the environment into the model and summarizes recent history better compared to a single-period snapshot. Specifically, we categorize our features into four categories that follow the structure of the environment: \textit{inventory features}, \textit{demand features}, \textit{fulfillment features}, and \textit{identity features}. While inventory features capture the stock a warehouse currently holds or has in transit, demand features summarize the home-region demand a warehouse observes. Fulfillment features record how much of incoming demand a warehouse served and where it shipped and identity features identify which warehouse an observation belongs to. A comprehensive list of the features used in our implementation is provided in \autoref{tab:obs-features}.

We approached the feature design with three central objectives in mind. First, we aimed to improve convergence speed and stability by designing features that simplify action selection. Take, for instance, the pipeline vector $\mathbf{P}_{ikt}$. By tracking the arrival slots of units it has already ordered but not yet received, the agent can optimize its behavior through ordering only the remaining shortfall rather than reordering stock that is already in transit. Second, we intended to provide the agents with deeper insights into the environment by combining, and in some places replacing, multiple raw inputs into a single more meaningful feature. One example is the days of supply $\mathrm{DoS}_{ikt}$, which expresses an agent's stock as the days of average recent demand it can cover. By combining inventory and average demand, we expected this feature to help the agent judge whether it is over- or understocked more effectively at each decision step. Similarly, the expected net inventory $I_{ikt}^{\mathrm{net}}$ gives the stock that the agent can expect to hold once all outstanding orders have arrived and lead-time demand has been served and thus might function as an early indicator of potential shortfalls. Finally, these engineered features allow us to reconcile single-observation networks with the history-dependent policy class defined in [\textbf{section POMG}]. By embedding past demand dynamics directly into the current observation trough features such as $\mathbf{D}_{ikt}$ or $\bar{D}_{ikt}$, a feedforward network reading only $o^i_t$ can successfully approximate a policy conditioned on the history $\mathbf{h}_t^i$.

However, it is important to note that we developed these features based on our empirical intuition rather than a theoretical framework. While they are designed to enhance learning and decision-making, there is no guarantee that each feature will improve performance. Indeed, some may duplicate information that another feature
already captures and others may enhance training efficiency at the expense of generalization and robustness. For this reason, we do not fix the feature set in advance and instead make feature selection a central part of our tuning process (see \textbf{autoref{sec:hyperparameter-tuning}}). The only two features we keep active in every configuration are the on-hand inventory $I_{ikt}$ and pipeline vector $\mathbf{P}_{ikt}$ since we consider them the basis of any ordering decision.

Formally, we partition the features of \autoref{tab:obs-features} into the default inputs $I_{ikt}$, $\mathbf{P}_{ikt}$, $\mathbf{e}_i$ and a catalogue of tuneable blocks $\{\phi_1, \dots, \phi_M\}$, where each block $\phi_m$ returns a real vector from agent $i$'s local history $\mathbf{h}^i_t$ and contains either the latest entry or a trailing window of recent observations from $\mathbf{h}^i_t$, depending on the feature. This catalogue serves as the basis for our tuning process, which selects features by choosing a specific configuration that activates a subset of blocks $\mathcal{B} \subseteq \{1, \dots, M\}$. The local observation of agent $i$ is then the concatenation of the default parameters and the active blocks in a fixed order, 
\begin{equation}
\label{eq:observation}
 o^i_t = \big[\, \mathbf{e}_i,\ (I_{ikt})_{k \in \mathcal{K}},\ (\mathbf{P}_{ikt})_{k \in \mathcal{K}},\ \big( \phi_m(\mathbf{h}^i_t) \big)_{m \in \mathcal{B}} \,\big] \in \mathbb{R}^{d},
\end{equation}
where $d$ is the summed width of the default and active blocks. Under this convention, each agent $i$ has a single local observation that is a deterministic function of its history, \(o^i_t = O^i(\mathbf{h}^i_t)\). Since all $W$ local observations share identical features, concatenating them yields the global observation $z_t = (o^1_t, \dots, o^W_t)$, which can directly be used by a centralized critic.

The final input vector to the \gls{acr:nn} combines all included features of a specific observation $o_t^i$ into a flat array. To ensure the dimensionality of $o^i_t$ remains strictly fixed throughout the episode, we zero-pad active blocks that summarize a trailing window of demand at the start of an episode until the window fills. Finally, we standardize every entry of $o_t^i$ to zero mean and unit variance using fixed statistics estimated once from a short random-policy rollout.\\

\subsection{Action design}
\label{subsec:action-design}
At the start of each period $t$, each agent $i$ chooses the replenishment quantity $q_{ikt} \ge 0$ for each \gls{acr:sku} $k$. While there are various possible formulations of the action space, a naive approach would have the policy directly output the replenishment quantities $q_{ikt}$ on a bounded continuous scale. However, we avoid this direct design for two reasons. First, because raw-quantity actions lack a physical anchor to the scale of demand, a randomly initialized policy would output arbitrary quantities at startup that are decoupled from actual environment requirements. The agent must then spend early training episodes on calibrating actions to a sensible range, which leads to inefficient exploration and reduces sample efficiency. Second, raw-action quantities are not scale-invariant, which causes a shared policy to suffer in heterogeneous environments. Specifically, since demand profiles can differ across warehouses and \glspl{acr:sku}, the policy not only must learn local scale factors from observations, but is also more sensitive to prediction errors due to the wider range of possible order quantities needed to span both low and high demand volumes. 

To address these issues, we adopt the $X+Y$ replenishment policy of [\textbf{CITE: Kimbrough et al. (2002), Preil and Krapp (2022)}]. According to this rule, the order quantity $q_{ikt}$ for each \gls{acr:sku} $k$ of each agent $i$ is determined by the two values $X$ and $Y$, where $X$ is the most recently observed home-region demand $D_{ik,t-1}$ and $Y$ is a variable adjustment to it. Therefore, each order quantity $q_{ikt}$ of agent $i$ can either exceed, fall short of, or be equal to the last observed home-region demand $D_{ik,t-1}$. Following our notation and adopting the $X+Y$ rule, the order quantities are thus determined as 
\begin{equation}
\label{eq:xy-action}
  q_{ikt} = \max\!\big\{0,\ D_{ik,t-1} + y_{ikt}\big\},
\end{equation}
where the $\operatorname{max}$ operator ensures that orders are non-negative and we set $D_{ik,-1} := 0$ so that the first-period order reduces to $q_{ik,0} = \max\{0,\ y_{ik,0}\}$. Since the deviations $y_{ikt}$ have to be determined for each agent $i$, \gls{acr:sku} $k$, and time $t$ separately, it follows that they replace the order quantities $q_{ikt}$ as the primary decision variables for each agent $i$ such that the final replenishments are only derived implicitly through \autoref{eq:xy-action}.

Adopting the $X+Y$ rule directly resolves the previously discussed limitations of raw-quantity actions. Because the policy now controls only the deviation $y_{ikt}$, a randomly initialized policy explores relative adjustments to demand rather than the order quantity itself. This keeps proposed orders within a bounded range near observed demand and thus skips the early training phase needed to learn demand scales. Expressing the action as a relative adjustment likewise removes the scale dependence issue since proportional deviations now carry the same meaning irrespective of absolute demand. A single shared policy can thus serve agents and \glspl{acr:sku} with differing demand volumes without inferring separate scales. Beyond addressing these scaling issues, the relative structure of the $X+Y$ rule offers an additional and arguably more important  key benefit. By restricting each deviation $y_{ikt}$ to the fixed range $\{-\Delta_k,\dots,\Delta_k\}$, we can effectively reduce the action space from all possible quantity vectors to a smaller set of demand-relative adjustments that the policy can search far more efficiently [\textbf{CITE: action-space reduction benefit of the $X+Y$ rule, preil and krapp mcts}].
